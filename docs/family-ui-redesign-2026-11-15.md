# 家庭做饭场景的 UI 重设计

## 判断与范围

此前的设计把“简单”固定成一张横线列表，首页、准备要求、设备参数、步骤和来源都偏向同一层级。它能快速比较几道食物，但普通家庭用户需要逐行阅读，才能分清哪些是开做前必须准备的内容。

用户于2026-11-15明确要求按当前产品和目标人群重写 UI，本次替换旧的视觉约束并更新 `design.md`。仍然是查找食物和照着操作的应用，不加入标语、营销模块、账户、收藏或计时器。

## 新界面

- **首页与分类页**：搜索仍在最前；六张实际食材照片辅助分类辨认，全部分类在手机上可见。做法使用整块可点击的独立条目，名称/条件在上，温度与时间在下，双阶段设置保留分段标签。桌面两列，手机一列。
- **菜谱**：开做前的强制准备以独立提示区展示，设备参数使用暖黄色区域，标签与数字区分。食材、编号步骤、熟透检查按实际使用顺序排列；工具、补充时间线与来源证据保留原生展开。
- **设置**：厨房单位预设与界面语言保持独立，使用原生选择框和清楚的保存按钮；保存成功、只能临时应用、无脚本状态仍由现有逻辑提供。
- **共享系统**：保留品牌图标、红色操作信号、自托管 DM Sans 和中文系统字体。新增共享分类导航与一个语义图标组件，无新增依赖；CSS 直接重组原样式而非再叠一层覆盖文件。

分类照片不代表某道菜的具体份量、冷冻/解冻状态、机器效果或本站实测成品。它们只存在于分类导航，不能覆盖菜谱条件。

## 保留对照

| 项目 | 本轮处理与验证 |
| --- | --- |
| 食谱、条件、温度、时间与来源 | 数据与搜索/设置/埋点脚本零修改；75道食谱、81个条件保持 |
| 默认可用库与单位 | 摄氏25道、华氏50道；保存一次配置，无新增全局换算开关 |
| 状态与模糊搜索 | 原搜索脚本保持；冷冻鸡翅仍只能看到明确标注的其他状态替代 |
| 网址、来源锚点与历史条件 | 改前/后保留93/93链接、3/3字段、20/20标题、1/1数字图表；历史条件与来源链接浏览器回归通过 |
| 配置持久化与语言 | 原字段/ID/事件保持；保存、重载、新标签页、存储失败与语言导航回归通过 |
| 统计与隐私 | 同意文案、按钮、事件、作用域与逻辑未改；测试拦截 Google 请求，不把本地检查当真实入流 |
| 无脚本与键盘 | 原生链接、表单、列表与展开组件保留，去掉默认符号的列表显式保留list角色；无脚本阅读、键盘分类选择、可见焦点通过 |

没有删除文件或路由，也没有把食物库卡片实现成新的状态容器。`food-index` 与 `variant-data` 继续由现有结构化数据生成，智能体和辅助技术无需读取另一套数据。

## 检查与复核

- `npm run check`：75个文件，零错误、警告或提示。
- 29项单元测试、数据校验和184个静态页面构建通过；原12组浏览器回归不改测试即通过，包括150次食谱/单位组合访问。
- 新增照片的六个本地资源实际加载通过；中英文、分类键盘选择及320–1920px布局专项检查通过。
- 真实页面检查：零失败、零警告，保留一项既有厂商手册长标题自然换行例外；保留项对照全部通过。
- 独立的全新上下文 reviewer 指出：初版手机分类区过高，只能看到一份完整食谱。已按意见缩小分类图片/内边距并收紧结果区，保留全部分类和至少44px的可点击区域；在390×844px下，中文第一道做法由约y500提前到y415，英文由约y522提前到y454；分类点击区域分别约86×64px和86×83px。

本轮仅提交 review 版本，未合并或发布。浏览器检查证明页面与交互可用；尚未进行真人厨房任务测试，不能据此宣称实际做饭成功率已提高。
