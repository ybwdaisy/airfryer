# 最小本机记录流程（设计稿，未接入应用）

目标：下次做同一种、同一起始状态的食物时，能找到自己上次的实际设置。继续沿用现有列表、菜谱页和原生表单，不增加推荐面板、账号或同步服务。

## 入口和流程

1. 菜谱的烹饪参数下方增加「记录这次」文本按钮。点击后在原位置展开表单，焦点移到第一个字段。
2. 自动带入食物、条件 ID、当前厨房配置和参考阶段，不让用户重新选食物。默认温度采用原生参考值；实际分钟数留空，避免把参考区间伪装为用户已经做过的结果。
3. 每阶段仅有两个必填字段：「实际温度（°C 或 °F）」和「实际时间（分钟）」。另有一项可选备注，例如「同一品牌，单层10个，中途翻面」。多阶段糍粑保留两组输入，不压成一个温度或总时间。
4. 点击「保存记录」后，在原参数下显示「我的记录」，包括阶段、记录日期和备注；原参考继续保留，不能被个人记录覆盖。允许「编辑」；删除可撤销。
5. 首页在原有列表中提供「我的常做」筛选，仍是一张列表。点击后回到原菜谱及条件，展示匹配当前单位的记录；无需新建仪表盘。

## 具体字段示例

| 位置 | 黑胡椒鸡胸肉 | 红糖糍粑 |
|---|---|---|
| 自动上下文 | 新鲜去骨、约180克、拍匀；公制 | 冷冻无馅长条，糖浆与黄豆粉另放；公制 |
| 阶段1温度 | 200°C | 180°C |
| 阶段1实际分钟 | 用户填写 | 用户填写 |
| 阶段2温度与分钟 | 无 | 200°C，实际分钟由用户填写 |
| 备注 | 可选 | 可选 |
| 保存后 | 我的记录：原生温度、实际时间、日期 | 我的记录：逐阶段设置、日期 |

这只是字段与流程示例，没有创建真实个人记录，也没有表示某个个人参数已被本站验证。

## 数据和边界

- 使用可版本化的本地结构：`version`、记录 ID、`recipeSlug`、`conditionId`、`kitchenPreset`、原生 `unit`、`phases[]`、备注、保存时间及参考复核日期。界面和智能体读取同一份阶段数据。
- 同食物不同起始状态必须分开。冻鸡翅记录不能自动套给解冻鸡翅；熟制复热不能套给生制。
- 摄氏记录保留摄氏、华氏记录保留华氏。用户改单位后，不做小数换算并称为新机器档位，也不将另一套记录当可直接操作的记录。
- 不按一次结果给全库统一加减温度或时间。用户记录仅表达实际设置，不能证明食品安全或所有机器都适用。
- 温度、时间为有效整数；不得超过产品当前支持的设备边界。存储失败就保留填写内容并显示失败，不能假称已保存。
- 保存反馈明确「保存在当前浏览器」。后续实现须把导出/恢复与清理站点数据的影响一起验收；本轮不引入云同步来规避本地数据管理。

## 验收任务

- 第一次做完后，能记录实际分钟，而不是直接保存默认参考当作做过。
- 下次用同一条件从「我的常做」找回；切换语言不丢记录。
- 糍粑两段分别保存、恢复，不丢改温动作。
- 更换温标、状态或参考更新后，原记录仍可辨认，不能被悄悄转换或覆盖。
- 键盘可完成展开、填写、保存；出错保留输入，删除可恢复。

本设计供 review；本轮实现范围仍是内容补齐与搜索恢复。
