# 保存一次的厨房设置与统一食物库

## 结果

首页不再要求用户反复选择中国、美国或温标。页头统一进入「设置」，保存公制厨房（°C、克、毫升、厘米）或美制厨房（°F、盎司、量杯、英寸），并独立设置中英文界面。之后在同一浏览器访问、刷新或打开新标签页，都沿用已保存设置。

统一食物库共 72 道菜谱、78 个来源条件。默认列表只展示当前温标已有原生参考、可以直接照着操作的菜谱：目前公制 22 道、美制 50 道。搜索仍检索整个库，将缺少当前温标做法的食物单列为「其他匹配食物」。这是用户明确选择的过渡展示方式，并不代表另一套做法已经补齐。

打开尚未适配的食物时，页面明确说明缺少哪套温标参考，并引导寻找其他菜谱或进入设置；不将原参数机械换算后作为可执行步骤。来源记录仍可展开阅读。

## 单位与数据边界

- 所有烹饪温度、阶段、时间、食材状态、提前准备及来源事实保持原样；没有新增未经参考验证的烹饪方法。
- 烹饪设置使用参考原生温标。选择公制不会把 400°F 变成 204.4°C，更不会直接沿用原来的时间。
- 食材重量、容量和尺寸随厨房设置显示；原文中的温度及权威食品安全温度对照保留，不作为新的机器档位。
- 当前摄氏菜谱仍受最高 200°C 的既有数据约束。机器是否具备指定档位仍需核对；本次没有宣称已经覆盖全部机型或步进。
- 无 JavaScript 时可阅读来源原生单位的菜谱，并看到设置需要启用脚本的说明。

## 设置与兼容

- 首次使用依据浏览器明确的地区默认厨房单位；界面语言与单位独立，未保存语言时保留英文首页默认。
- 将旧版明确的单位偏好迁移一次。保存后的设置优先，旧分享链接的 `unit` 参数不能覆盖用户选择。
- 使用当前站点来源内的 `airfryer:kitchen:v1` 保存设置；没有账号同步，也不会改变其他子域名项目的设置。
- 浏览器拒绝持久存储时，明确显示「本次有效，无法保存到后续访问」。尝试使用当前会话存储，并通过受限的临时 URL 参数保持后续导航；切换语言后的设置页继续保留该提示。
- 所有旧菜谱路径、条件 ID、来源锚点仍可访问。旧分区首页和分类路径保留可达性，canonical 指向统一列表；设置页不索引。

## 埋点

保持原事件名和同意后采集的边界。新增设置页分类；保存时记录一次单位变化，跨语言导航通过经过校验的短期交接记录保留单位和语言事件，避免加载 SDK 时跳转丢失。

尚未适配的做法不计入指南浏览、阅读或分区参与。既有 `cn/us` 来源分组维度为兼容历史报表保留，不再显示为前台的国家分区。没有修改 GA4 后台探索或发送真实验证流量。
