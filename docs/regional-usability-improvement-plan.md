# 空气炸锅工具改进计划与方案自审

> 评审阶段存档。用户后续已确认标准并授权开发，当前实现与验收以 [地区化开发记录](regional-development-status.md) 为准。文内“先不改代码”等描述保留当时评审语境。

版本：2026-11-13。方向已获用户确认，目前停在内容样稿评审阶段；[五份完整内容样稿 v3](five-content-samples.md)按“看得懂、选得对、照着做得下去”重新整理。用户已明确：目标是应用简单易懂，腌制和先炖后烤均可保留，所需厨具、前处理与分阶段时间必须提前说明。样稿正文提供完整操作，编辑调整与来源核查另列；尚未完成本站实机烹饪测试。**不修改产品代码、不改线上数据、不部署；内容样稿未获评审前不进入实施。**

## 1. 这次要解决的问题

产品的目标是：用户拿着自己买到的食材，能找到相符的做法，直接设置炸锅并知道何时检查熟度。验收对象是这件事能否完成，而不是中文是否翻译齐全、页面是否构建成功。

**用户进一步确认的内容原则：应用应简单易懂，不以菜谱步骤最少或仅用一台设备作为收录目标。** 腌制按菜式需要保留，等待时间提前列明；先炖后烤可以保留，搜索结果与详情开头必须写明“需要炒锅＋空气炸锅，无法只靠空气炸锅完成”。不得因需要腌制、其他厨具或特定工具而自动淘汰有效做法，也不得为了显得简单而删掉必要步骤。

当前实现已核实的事实：

- 50 个食物条目、55 个条件，两种语言共用同一食物库和排序，没有地区选择。
- 单位开关只转换部分炸锅温度；分量、厚度、步骤和安全说明仍有独立的英制文本。中文默认也使用华氏度。
- 鸡块、鱼条、部分烘焙等记录实际依赖美国具体产品，不能泛化为国内同名食品的做法。
- 同名食材不代表同一道菜。例如现有茄子是帕尔马干酪裹片做法，不能换个中文名字就作为中式烤茄子。
- 中文测试曾要求逐字保留英文数字和温度单位；这检查了翻译对应关系，却固化了不适用的使用体验。
- 过去的来源抽检、截图审查与构建检查，没有证明中国家庭或美国家庭能顺利完成一次真实查询。

原始可行性报告以欧美用户为起点，但用户现在已经明确要求地区化使用体验；旧报告不是继续套用同一套内容的理由。报告中的自动重量修正等建议也不直接作为实施授权。

## 2. 建议的产品方向

先做好两个明确的使用环境：**中国家常、美国常见**。英文保持默认语言。暂不把美国版称为覆盖整个欧美，也不急着增加法、德、日、韩语言。

地区入口是经过编辑的食物集合，不是对一个国家所有人的饮食定义。牛排可以在中国集合中被主动搜到，但不应仅因现有数据齐全就占据默认高优先级。

| 层面 | 决定什么 | 不应顺带改变什么 |
|---|---|---|
| 界面语言 | 名称、说明、搜索表达、界面文字 | 用户明确选过的地区和单位 |
| 饮食地区/集合 | 推荐食物、常见做法、当地产品适用性、默认排序 | 某一道已选做法的烹饪事实 |
| 计量偏好 | 全部操作指引的温度、重量、长度和体积表达 | 分量增加后的时间、冷冻与新鲜的等价关系 |
| 食物及具体做法 | 生熟、切法、厚度、分量、是否裹粉、品牌限制 | 不允许仅凭同名食物推断另一种做法 |

首次进入可以提供预设：中国家常用公制，美国常见用美制；页面明确显示当前选择，用户可独立更改。第一次打开仍为英文；中文首次入口可建议中国家常预设。已有明确选择时，切语言不重置地区、单位或做法。不通过 IP、姓名或语言猜测民族与宗教。

“民族风格”落实为有来源支持的具体菜式和用户主动选择的饮食偏好，不做“某民族必然吃什么”的自动归类。素食、不吃猪肉等筛选只有在配料标注完整后才加入；不能凭食物名声称清真、过敏原安全或其他认证。

## 3. 食物库怎么重新组织

建立“食材 → 具体做法/状态 → 适用条件”，地区只选择、推荐这些记录。同一条做法在中英文中保留同一组事实；中式烤茄子与干酪裹茄子应是不同做法。

不再以凑够 50 个名称为目标。先评审下面每个地区约 20 项的候选池，再按来源完整度和任务覆盖确定首发数量；候选不等于承诺上线，也不等于已经证明当地高频。

| 中国家常候选 | 美国常见候选 |
|---|---|
| 鸡翅：分清翅中/翅根、是否腌制 | Chicken wings：split wings |
| 鸡腿：区分小腿与整腿 | Chicken drumsticks |
| 鸡胸：原切或切块分别查证 | Chicken breast |
| 排骨：切段、带骨、腌制条件明确 | Pork chops |
| 五花肉：薄片与厚块分开 | Steak：明确部位与厚度 |
| 虾：带壳与去壳分开 | Salmon fillets |
| 带鱼段：厚度与是否裹粉明确 | Shrimp |
| 豆腐：老豆腐/嫩豆腐不可混用 | Burger patties |
| 茄子：中式对半烤的独立做法 | Bacon |
| 花菜：切块与调味方式明确 | Broccoli |
| 蘑菇：品种、整颗/切片明确 | Brussels sprouts |
| 玉米：整根/切段明确 | Asparagus |
| 红薯：整根大小有适用边界 | Potatoes：块状/整颗分别收录 |
| 土豆块：切块大小明确 | Sweet potatoes |
| 藕片：厚度与起始状态明确 | Frozen fries |
| 馒头片：厚度、刷油或裹蛋分开 | Frozen chicken nuggets：产品状态明确 |
| 蛋挞：挞皮、挞液、模具条件明确 | Frozen mozzarella sticks |
| 冷冻薯条：粗细和包装条件明确 | Garlic bread |
| 面包复热：非生面团烘烤 | Pizza reheating |
| 熟炸鸡复热：非生鸡肉烹饪 | Grilled cheese：新做而非复热 |

候选筛选顺序：用户是否会这样搜索 → 能否买到对应食材/产品 → 条件是否容易辨认 → 是否有足够来源支持 → 能否不做心算地操作。来源方便找不能替代需求判断。

现有 50 项逐条处理，而不是全部删除或全部保留在首页：

1. 可跨地区使用、条件充分的，保留并改进表达。
2. 做法不同的，另建做法，不能只改名字和调味词。
3. 美国特定产品，归入相应产品/地区，名称和搜索结果直接标明限制；中国通用搜索不将其冒充通用答案。
4. 日常优先级低但内容有效的，仍可检索，不挤占默认推荐。
5. 条件不充分、来源冲突未解决的，暂不作为推荐答案。
6. 中国集合以最高 200°C 的家用机器为兼容基线；确实依赖超过 200°C 才能完成的做法，不收录到中国集合，不通过跨集合补充结果绕过此限制。若有来源充分、全程不超过 200°C 的另一种做法，可独立评审收录。

不通过隐藏全部非本地内容制造搜索死路。跨集合结果可作为明确标注的补充；没有合适做法时说明缺少哪种条件，不自动套用相近食品。

## 4. 一条结果必须能直接使用

首屏按做饭顺序组织：**这是不是我手上的食物 → 开始前需要的处理、厨具与工具 → 各阶段时间 → 按顺序操作 → 完成检查与未完成时的下一步**。已经满足前处理的用户可以跳到烹饪段，但不能因此改变适用食材或参数。来源详情放在后面展开，必要的产品限制和前处理不能藏进来源区。

- **准备、等待、烹饪、静置分别说明。** 鸡翅的腌制时间与气炸时间分开；排骨的煎炖、收汁、预热、气炸分开；时间没有依据的阶段以明确完成状态引导，不编造总耗时。气炸时间明确为每批参考。
- **工具依赖在操作之前说明。** 温度计不加入所有食物的统一工具清单；实际依赖测温的具体指南提前提示，不能在结束步骤才告知。家庭观察提示须有可靠依据，并说明不能精确测量中心温度；不得通过删掉测温指导来承诺固定分钟数保证安全。
- **一次说清一件事。** 分段温度逐步写出，阶段更换时交代是否翻面、加料或重设温度，避免把几个动作挤进一个长句。型号操作补充与通用动作分开，适用型号边界仍要可见。

- 公制下，条件选择、分量、尺寸、操作步骤、炸锅设置和中心温度统一使用公制；美制下同理。对照单位放在可展开说明中，不让两套数字在主要操作区竞争。
- 明确“每块重量”“食谱总用量”“一次入锅量”。原食谱用了某个总重量，不代表小炸篮能一次放完。
- 保留原始测量与来源精度；显示换算使用约数并说明规则。不能把缺失的厚度、大小上限或单块重量补出来。
- 体积不能在不知道食材密度时直接换成重量；来源没有重量时，优先保留可辨认的数量/体积条件。
- 炸锅旋钮温度与食物中心温度分开标识。旋钮档位取整需要单独制定规则；安全终点不能沿用同一个取整函数。
- 时间是该条件下的参考检查区间，不承诺每台机器到时必熟；不添加按重量、冷冻状态随意加百分比的公式。
- 若来源要求盐水浸泡、特定涂层或其他影响结果的准备，必须提供足够操作信息，或换一个能独立说明完整的参考做法。不能让用户到最后才发现还得读英文长文才能开始。
- 分享链接保留具体做法和条件；切地区不能悄悄让同一链接变成另一套温度、时间。旧链接与原有来源仍可追溯。

### 4.1 中国版设备温度上限与档位适配（用户已确定的约束）

**中国版优先兼容最高温度为 200°C 的家用空气炸锅；必须依赖超过 200°C 的场景直接放弃，不为了覆盖少数高温机型而收录。** 这是产品范围约束，不代表宣称中国市场所有机器都以 200°C 为上限。

- **检查完整过程。** 预热、主烹饪、分段加热及最后上色均须不超过 200°C；不能只让主温度合规，却在步骤中要求更高温度。
- **先核对设备可设档位，再确定展示规则。** 在内容评审阶段抽查国内家用机型的官方说明书，记录温度上下限、调节步进或固定刻度，以及对应模式；不能假定每台机器都有 5°C 步进或都能设置 195°C、205°C 等数值。无需为此先建设完整型号库或增加强制选机流程。
- **不把换算结果当成可执行档位。** 原始 400°F 约为 204.4°C，机械取整为 205°C 不构成中国版的适配做法。中国版应优先采用直接支持摄氏度可设档位、条件完整的参考做法。
- **不静默降温或自动补时间。** 不能将来源中的 205°C/400°F 截成 200°C 后沿用原时间，也不能自行增加若干分钟。存在有来源支持的 200°C 或更低温替代做法时，单独记录其条件、时间与依据；没有则暂缓收录。确认该场景确实必须超过 200°C 才能完成时，从中国版范围中排除。
- **档位不匹配不靠猜。** 参考做法温度不在所核对设备的可设档位中时，先寻找有依据的可执行做法；没有依据时，不把“取最近档位”当作已验证适配。明确兼容范围，不能声称覆盖所有 200°C 上限机型。
- **安全终点另行处理。** 此处的上限和档位仅指设备设定温度；食物中心温度的安全要求不能随旋钮档位取整、下调或删除。

### 4.2 美国版设备温度上限与档位适配

美国版同样按家用机器的实际能力筛选做法，建议本阶段以 **400°F 为最高设定温度的兼容基线**，日常操作默认使用华氏度。此处是产品覆盖范围选择，不是宣称所有美国机器的上限都是 400°F，也不是市场份额结论。

2026-11-13 核对的美国官方产品资料示例：[Ninja AF101](https://www.sharkninja.com/ninja-air-fryer/AF101.html) 标明 105–400°F；[Instant Pot Vortex Plus 4QT](https://instantpot.com/products/instant-pot-vortex-plus-4qt-air-fryer) 标明 95–400°F。这些资料支持将 400°F 作为当前版本的起步基线；尚不构成所有模式和档位的兼容验证。

- **全程不超过 400°F。** 预热、主烹饪、分段加热及上色一并检查。当前版本不收录必须依赖更高设定温度的做法；不能将超过上限的参数直接截成 400°F 后保留原时间。
- **核对美国型号与实际模式。** 收集官方说明书中的模式温区、调节步进和固定档位，不能以同品牌中国版、欧洲版或高温特殊模式的能力替代美国型号的 Air Fry 能力。不能假定所有机型支持每隔 5°F 或 10°F 调整，也不能仅凭上限相同就宣称兼容。
- **华氏度来源仍需适配审查。** 来源写 375°F、380°F 或 390°F，并不自动证明用户机器都能设置；档位不匹配时寻找有来源支持的替代做法，没有依据则不声称兼容，不自行取整并补算时间。
- **两地上限分别处理。** 400°F 约为 204.4°C，不能视为与 200°C 相同。美国来源的 400°F 做法不能因切成中文就归入中国集合；中国集合也不能因切成英文而放宽 200°C 上限。切换显示单位不会改变适用机器范围。
- **延续相同的证据标准。** 每块/总量/入锅量、前处理、产品限制、熟度终点与适配依据都要检查；美制表达正确不等于美国版已经可用。美国设备资料抽查和任务样稿也必须在实施前完成。

## 5. 作者与来源怎么 review

过去“有两个链接”“数字抄对了”不够。后续逐条区分三件事：

| 审查对象 | 需要核实 | 不足时的处理 |
|---|---|---|
| 来源作者/发布者 | 原创作者还是转载；品牌原始说明还是泛用文章；是否能识别版本/型号/产品 | 不将转载计为独立验证，厂商说明保留产品边界 |
| 具体做法 | 生熟状态、切法、用量、前处理、机器模式、分批、温度与时间是否一致 | 不平均两个不同做法的数字，不拼成一条虚假的共识记录 |
| 本站使用说明 | 脱离原长文能否操作；是否改变了作者的关键步骤；安全终点与食谱追求的口感是否冲突 | 补足条件、明确差异；必要时暂缓推荐 |

已有审计报告提示：某些交叉参考条件不同，以及部分肉类/海鲜来源的出锅建议与本站安全要求存在差异。实施前需重新确认页面当前内容，并检查已发布说明是否充分。历史审计不能直接当成今天重新核验的结果。

厂商参数、独立菜谱参考、实际烹饪验证必须分别标记。现阶段不能声称本站做过实机烹饪测试。

| A. 方向评审，本轮 | 本计划、候选清单、下方反向审查 | 用户确认方向后，开始内容样稿 |

## 7. 验收要看使用任务

以下是计划中的验收，不是已完成的测试：

1. **中国家庭查鸡翅：** 手机中文页面直接看懂具体部位、分量和准备，完成设置、翻面及熟度检查；操作区无需认识华氏度、盎司或英寸。
2. **中国家庭查排骨：** 找到对应切段做法，能识别自己手里的排骨是否适用；先炖后烤做法在选择时已显示需要炒锅＋空气炸锅，用户不会把气炸 7 分钟误认成整道菜耗时。没有相符做法时，不返回猪排或牛排参数凑答案。
3. **国内冷冻鸡块：** 不把“完全熟制美国某品牌鸡块”的参数当成任意国内生制鸡块的参数；包装说明优先关系清楚可见。
4. **美国用户查 chicken breast：** 依照自己的一块鸡胸选择条件，美制数字贯穿操作；食谱总用量不被当作一次入锅量。
5. **同一食材不同做法：** 搜茄子能识别中式对半烤与干酪裹片的区别，不因切语言变成另一道菜。
6. **组合偏好：** 英文 + 中国集合、中文 + 美国集合都成立；更换语言不覆盖明确选项；刷新、分享、返回和旧链接保持条件含义。
7. **缺项与异常：** 未收录的食物、缺失大小范围、品牌不符、来源冲突，都能诚实说明，不能自动外推。
8. **最高 200°C 的机器：** 中国集合内的所有可执行做法，预热、主温度和全部步骤都不超过 200°C；确实依赖更高温度的场景不出现在该集合或其补充答案中。检查现有 400°F 条件时，不能将 205°C 改成 200°C 就算验收通过，替代做法必须有独立记录的依据。
9. **设备档位不匹配：** 按所核对说明书的实际可设档位检查样稿，不能要求用户设置机器没有的温度，也不能随意取邻近档位并承诺时间不变；无适配依据则不宣称兼容。
10. **美国设备适配：** 美国集合按 400°F 基线检查全程设定与具体型号的模式/档位；不能因原菜谱使用华氏度就跳过审查。更换界面语言或显示单位不改变适用范围，不将 400°F 做法自动当作中国 200°C 适配做法。

验收时请使用者讲出“我现在拿的是什么、下一步做什么”，记录误选、回退、求助和额外换算。先做制作者逐任务检查，再尽量让目标使用者试用；没有真实用户证据时，结论只能是“内部任务检查通过”。原报告的“3 秒查到”作为待测目标，不写成已达成事实。

自动检查用于守住单位一致性、条件和来源完整性、偏好持久化、链接与现有功能；它不能替代内容适用性与厨房使用验证。

## 8. 方案反向审查

本节是制作者自审，**不是已经获得的独立用户评审**。

| 可能再次走错的方向 | 本计划的约束 | 仍需验证的部分 |
|---|---|---|
| 把“美国偏见”换成“中国偏见” | 两个集合均为候选编辑清单，允许跨集合搜索，不以国籍推断个人饮食 | 哪些食物和做法值得排在前面 |
| 有地区按钮，内容依然同一套 | 以具体做法和当地产品适用性决定收录，示例卡先验收 | 中国排骨、茄子等是否具备独立完整来源 |
| 单位全换了，仍然无法开始做饭 | 五份样稿先检查前处理、批量与检查步骤 | 新手能否理解并操作，不依赖原文补课 |
| 把“应用易懂”误解为“菜谱必须省事” | 保留有依据的腌制和多厨具做法，提前交代准备、工具和完整顺序 | 用户开始前能否说清需要什么、先做什么、哪些时间只是某个阶段 |
| 为了尽快上线再次凑数 | 不设必须保留 50 项的门槛；缺来源就暂缓 | 首批实际可用覆盖量 |
| 过度增加设置，让速查更慢 | 首次给清楚的预设，后续记住选择，查询不要求反复设置 | 手机中地区/单位选择的可发现性与负担 |
| 两个来源被包装成两次实测 | 分开标注参考、交叉核对与实测，不许泛化不同条件 | 每条来源独立性、差异是否足够透明 |
| 单位正确，却要求机器设不了的温度 | 中国集合全程不超过 200°C，美国集合按 400°F 基线筛选；分别核对型号、模式和实际档位，不静默降温和沿用原时间 | 两地样本机型的模式、温度范围与步进，以及替代做法的来源是否充分 |
| 复杂架构拖累一个生活小工具 | 保持静态站和现有设计，仅增加必要的内容模型 | 数据维护工作量是否可持续 |

建议先批准的范围只有：**中国家常 + 美国常见两个集合的方向，以及先做五份内容样稿的流程。** 食物优先级、首发数量、具体烹饪参数都在样稿与盘点后再定，不在本轮提前锁死。
